# Нейро-стенографист — Android, офлайн-расшифровка диалогов (Nuclear IT Hack)

## Цель
Android-приложение (Kotlin), которое ЛОКАЛЬНО превращает аудиозапись разговора в текст,
определяет говорящих (диаризация) и выдаёт структурированную расшифровку с таймкодами.
Результат: просмотр в приложении + экспорт в JSON-файл. Дедлайн: сегодня 23:00 (UTC+5).

## Как будут оценивать (из презентации) — расставляй приоритеты по этим баллам
| Критерий | Баллы |
|---|---|
| Точность транскрибации (WER, пунктуация входит, ё=е) | 40 |
| Точность диаризации | 25 |
| Точность временных меток | 10 |
| Скорость (RTF, ранжирование относительно других команд) | 10 |
| Работоспособность и UX | 10 |
| Защита | 5 |

Проверка: эксперты ставят APK, импортируют 3 тестовые записи диалогов, запускают
транскрибацию+диаризацию, экспортируют JSON, сравнивают с эталоном (WER) и меряют RTF.
Стенд: ARM (arm64-v8a), ~4 ГБ RAM, телефон среднего сегмента. Записи могут быть длинными.

## Обязательные требования (без них — не допуск)
- Android, всё на устройстве, работает БЕЗ интернета. Никаких облачных API.
- Модели ВСТРОЕНЫ в APK (assets). Догрузка из сети — только опциональный UX-бонус.
- **Используется локальная LLM** (явное требование презентации, базовый уровень).
- Импорт аудио из памяти устройства (SAF, любые распространённые форматы → 16 kHz mono).
  Запись с микрофона в приложении — желательно (упомянута как вход).
- ASR, автоматическая диаризация, start/end для каждой реплики.
- Отображение расшифровки в приложении + экспорт в файл.
- Языки: русский — приоритет 1, английский — приоритет 2.

## Формат JSON (СТРОГО, из презентации)
```json
{
  "transcript": [
    { "speaker_id": "speaker_1", "start_ms": 1250, "end_ms": 4380, "text": "Добрый день!" }
  ]
}
```
- `speaker_id`: string, `speaker_1`, `speaker_2`, … (с 1, по порядку первого появления).
- `start_ms`, `end_ms`: integer, миллисекунды от начала файла.
- `text`: string, с пунктуацией и заглавными буквами. Реплики отсортированы по start_ms.
- Никаких лишних полей на верхнем уровне. Доп. данные (summary LLM и т.п.) — в отдельный файл.
- Имя файла экспорта: `<имя_аудио>.json`, сохранение через SAF/в Downloads.

## Стек
- Kotlin + Jetpack Compose, minSdk 26, ABI arm64-v8a (+ x86_64 только для отладки на эмуляторе, если нужно).
- sherpa-onnx (AAR/JNI): VAD + ASR + speaker diarization.
- ASR RU: GigaAM (вариант, поддерживаемый sherpa-onnx; если есть вариант с пунктуацией — предпочесть его,
  иначе пунктуация отдельно). int8-квантизация, если точность почти не падает.
- ASR EN: небольшая модель (Whisper tiny/base или Zipformer EN), выбор языка — авто или переключатель.
- Диаризация: pyannote segmentation-3.0 + speaker embedding (3D-Speaker/NeMo) через sherpa-onnx;
  кластеризация с порогом; если число спикеров задано пользователем — использовать его.
- Локальная LLM: llama.cpp (JNI) + маленькая instruct-модель в GGUF Q4 (~0.5–1.5B, напр. Qwen).
  Роль LLM (по приоритету):
  1. Восстановление пунктуации/регистра С ЗАЩИТОЙ: результат принимается, только если после
     нормализации (нижний регистр, без знаков, ё→е) последовательность слов НЕ изменилась.
     Иначе — оставить исходный текст. LLM не должна менять слова (это бьёт по WER).
  2. Краткое резюме встречи / итоги / задачи — отдельной кнопкой, вне основного пайплайна (не портит RTF).
  Если ASR уже даёт хорошую пунктуацию — LLM только для п.2, и это нормально.

## Память и скорость (4 ГБ RAM)
- Модели загружать последовательно и выгружать: ASR+диаризация → освободить → LLM.
- Длинные записи: декодирование потоком, обработка по сегментам VAD/диаризации, без всего PCM в RAM сверх нужного.
- Тяжёлая работа — в foreground service/WorkManager с прогрессом; экран не должен блокироваться.
- Логировать время каждого этапа и RTF в logcat (тег `STENO`).

## Цикл проверки (главное для автономной работы)
- Сборка: `./gradlew assembleDebug 2>&1 | tail -40`
- JVM-тесты: `./gradlew testDebugUnitTest 2>&1 | tail -40` (формат JSON, склейка реплик, нормализация).
- На устройстве/эмуляторе: `adb install -r ...apk`; debug-интент/инструментальный тест берёт
  `test_audio/*.wav`, пишет JSON в `/sdcard/Download/steno/`; `adb pull` → `eval/out/`.
- Оценка: `python3 eval/score.py eval/out eval/ref` → WER (нормализация ё→е, регистр, знаки отдельно
  и с пунктуацией), DER/точность спикеров, ошибка таймкодов, RTF. Результаты дописывать в
  `artifacts/test-results/results.csv`.
- Шаг считается сделанным, только если сборка зелёная и score не ухудшился.

## Правила работы агента
- Не задавай вопросов — принимай разумное решение и записывай его в `NOTES.md` (1 строка на решение).
- После каждого зелёного шага: `git commit` с понятным сообщением.
- Экономия контекста: НИКОГДА не читай бинарники и модели (`*.onnx`, `*.gguf`, `*.bin`, `*.aar`, `assets/`),
  логи gradle/logcat всегда обрезай через `tail`/`grep`. Не перечитывай файлы без нужды.
- 3 неудачные попытки подряд — откат, запись в NOTES.md, запасной путь.
- Приоритет: рабочий APK (импорт → ASR RU → диаризация → JSON → экран) > WER RU > диаризация >
  LLM (минимум, но обязательно) > таймкоды > RTF > EN > UX-полировка > догрузка моделей.
